Challenger — Stable Model

Challenger — Live Read

A separate model, NOT a variant of the k-NN above. When today is regime-anomalous (the same tripwire the k-NN itself flags), this defers to a simple, transparent trend-persistence read instead of trusting the k-NN's own number in exactly the conditions it's been empirically bad in. When NOT anomalous, it defers to the k-NN's own p_up — on the theory that when today DOES resemble history well, the k-NN's own logic is the more trustworthy read. The "Tilted" variant additionally nudges the flat read using Foufi's daily short-term driver tag (macro/tradfi only) and his stated lean for that category, when a fresh (≤30h) digest has one. The trend-strength bar below is a separate guardrail (dampens, never flips, a call that disagrees with a strong MA-slope trend) — shown for transparency on what nudged this specific read, not a forecast itself. Pure comparison logging — this does not feed the Dashboard prediction above, the Regime Scorecard, or anything else.

Experimental — undecided design choices

Combined Accuracy — which formula?

Simple average treats all 4 coin/horizon combos equally regardless of how many resolved predictions back each one. Pooled (n-weighted) is mathematically the same as Σcorrect/Σresolved — a combo with 150 resolved predictions gets proportionally more say than one with 20. They're the only two meaningfully different formulas; a third "weighted by n" option would just be pooled again.

Selected Model —

The "council build" — Condition-Matched Selection. Not "which variant has the best recent accuracy" (that's the shallow, explicitly-rejected approach this session already identified as noise-chasing) — instead, "among historical moments that looked like THIS one, which variant was actually right when it made THIS SAME directional call." A variant needs 50+ resolved predictions of its own before being considered, and its local edge must clear a significance bar that gets stricter the more variants are being compared. If nothing clears the bar, it explicitly falls back to Original k-NN rather than forcing a confident-looking pick — that fallback is the common, healthy state early on, not an error.

Model Health & Recent Trend — is it actually improving?

"Recent" is the last 40 resolved predictions for each combo; "Prior" is everything before that — computed by differencing the same expanding-window data the charts above already use, not a separate fetch. This exists specifically to answer "did that last fix actually help" without needing to remember what the numbers were last time or query the database by hand. A combo with fewer than 50 total resolved predictions doesn't have enough history yet to split meaningfully and shows as pending instead of a misleading number. Recent sample sizes here are still small (30-50) — a single-digit swing is normal noise, not a verdict.

The indented "↳ Calibrated" rows are a genuinely different thing from the row above them, not a duplicate: they're a probability adjustment built from that model's OWN accumulated resolved history (decile-bucket recalibration, rebuilt daily), reused as-is for both the core model and Challenger. Never replaces the row above it — shown separately so whether this adaptive layer actually helps gets decided by watching it over real time, not assumed on the way in. Needs its own 20+ resolved predictions before the underlying curve exists at all, on top of the 50 this table already requires — will show "not enough history" for longer than the row above it, that's expected.

Learning Loop
