# V3 Alignment Audit

Scope: `quiquandon-oss/CryptoPulseV3`, audited against `quiquandon-oss/CryptoPulseV2` (original frontend, `CryptoPulse V2 — BTC Prediction Model`, commit `8e53faf`) and `quiquandon-oss/PulseWorkerV2` (backend, commit `9e6ad00`). Note: `quiquandon-oss/CryptoPulse` (no version number) is a **different, unrelated app** — a portfolio/DCA/cost-basis tracker hitting a different Worker (`sentiment-ff75...`) — and is not part of this audit despite being linked from V3's footer as "Data: shared with CryptoPulse."

## 1. Branch structure — the ambiguity

This repo has **no `main` branch**. Its GitHub default branch is `copy-cryptopulse-v1-2030101685376706320` — an auto-generated name from whatever import/migration created the repo. All actual development happens on a single harness-designated branch, `claude/cryptopulse-v3-dashboard-3gnovn`, which is repeatedly merged into the default branch and then recreated from its own tip for the next round of work (visible in `git log` as a long chain of `Merge pull request #N` commits). `.github/workflows/deploy.yml` originally watched `main` and therefore never fired even once until that was corrected to watch the real default branch (fixed in PR #15).

**Practical effect:** "the canonical V3 branch" is not a stable name — it is whatever `claude/cryptopulse-v3-dashboard-3gnovn` currently points to, which gets reset after every merge. At the time of this audit, that branch is one commit ahead of the merged default branch (an open PR, #17, with a widget bug fix and a D1-quota-driven refresh-interval change) — this audit and its corrections build on that tip, since it is the most current intended state, not the slightly-stale merged default branch. This is a structural quirk of how this session's tooling works, not a mistake to "fix"; it's documented here so it isn't mistaken for a real branch/version ambiguity in the product itself.

There is exactly one frontend implementation in this repo (`index.html`), plus two smaller pages added this session (`widget.html`, `widgets.html`) that duplicate a trimmed copy of the same data-normalization logic. There is no separate "v3-alpha" or competing implementation to disambiguate.

## 3. Backend contract fields actually available (confirmed from `PulseWorkerV2/worker.js`)

- `selection_decisions`: `ts, coin, horizon_hours, prediction_ts, chosen_variant, chosen_p_up, lca_score, cleared_gate, comparison_count`, plus (per the anomaly-gate sibling table) `k_sel`/`neighborhood_json`-shaped fields exist in that experiment's schema; not confirmed whether the base production table carries `neighborhood_json` — needs a live response check, not assumed.
- `challenger_predictions`: `p_up_flat, p_up_tilted, p_up_momentum, momentum_triggered, calibrated_p_up_flat, trend_strength, is_regime_anomaly, realized_up, realized_return, resolved_ts`.
- `/chart-data` (+ LINK/ETH siblings): returns full, **unbounded** `prices`/`predictions` arrays — the `days` param V3 sends is accepted by the URL but never used server-side to filter. This is a PulseWorkerV2-side inefficiency (already flagged separately re: D1 quota), not a V3 frontend defect, and is out of scope for this pass per the instruction not to modify PulseWorkerV2 without explicit need.

## 4. Summary of required corrections, by risk

**Critical (statistical integrity — fix unconditionally):**
1. Remove `generateMockCoinData()` fabrication on fetch failure.
2. Remove `generateFallbackSelections()` fabrication on empty selection history.
3. Remove `normalizePrediction()`'s direction/confidence/expectedMove defaults.
4. Remove the Learning tab's hardcoded fake "Active"/"Healthy" status claims.

**High:**
5. Remove `normalizeSelection()`'s `'Original k-NN'` guess-when-absent.
6. Read `chosen_p_up` from selection records instead of always using the raw prediction's own `p_up`.
7. Add freshness states (LIVE/RECENT/STALE/UNAVAILABLE).
8. Surface real fetch-failure reasons instead of silently falling back.

**Medium:**
9. Data-integrity panel.
10. Deviation calculation in the historical view.
11. Remove `loadComparisonCards()`'s guessed model-name fallbacks.

**Low (deferred — documented, not built this pass):**
12. Raw-vs-calibrated numeric comparison badge.
13. Neighborhood/analog detail disclosure.
14. Explicit 12H/24H toggle.
15. Explicit "Production impact: NO" badges on Lab cards (labeling refinement; the underlying separation is already sound).

Corrections 1-11 are implemented in this change. 12-15 are named explicitly in the Remaining Risks section of the final report rather than silently dropped.
